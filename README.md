## Preprocessing Steps

Full implementation in `02_data_preprocessing.ipynb`. Each step is backed by established recommender-system literature.

### Step 1: Load Raw Data
- Loaded all three CSV files from `data/raw/`
- Raw files are never modified (preserved for reproducibility)

### Step 2: Drop Unrated Movies (Cold-Start Items)
- Removed 7 movies whose `ratingId` has no corresponding entries in the ratings table
- **Justification:** Items with zero interactions are *cold-start items*. Collaborative filtering requires user-item interaction history to compute similarity or learn latent factors. Items with no ratings provide no signal for any CF approach.
- **Reference:** Schein et al. (2002); Lika et al. (2014) — see References below

### Step 3: Deduplicate by tmdbId
- 4 movies appeared twice with the same `tmdbId` but different `ratingId`
- Kept the entry with the most ratings for each `tmdbId`
- **Justification:** Duplicate records violate data integrity and can bias model training. In recommender systems, duplicated item entries cause the same movie to appear multiple times in the user-item matrix, distorting similarity computations.
- **Reference:** Ilyas & Chu (2015) — see References below

### Step 4: Parse JSON Columns (Feature Extraction)
- Converted `genres` from JSON string to list: `'Comedy|Crime'` and `['Comedy', 'Crime']`
- Converted `keywords` from JSON string to list
- **Justification:** Content-based and hybrid recommender systems rely on item metadata (genres, keywords) to model item characteristics. These features must be extracted from raw storage formats into structured representations before use.
- **Reference:** Lops et al. (2010) — see References below

### Step 5: Compute Rating Statistics
- Calculated `avg_rating`, `num_ratings`, and `rating_std` per movie
- Merged into the movies table
- **Justification:** Rating frequency and value distributions significantly impact recommender system performance. Understanding these characteristics helps with filtering low-quality items and setting minimum support thresholds.
- **Reference:** Adomavicius & Zhang (2012) — see References below

### Step 6: Merge Tables
- Merged credits (cast, crew) into movies on `tmdbId`
- Enriched ratings with movie title and genres for readability
- Rationale: Denormalised dataset avoids repeated joins during algorithm development

### Step 7: Sparsity Analysis
- Computed user-item matrix dimensions and sparsity ratio
- **Justification:** Sparsity is a fundamental challenge in CF. Real-world matrices are often >99% empty, which motivates matrix factorization (SVD) over neighbourhood-based methods.
- **Reference:** Koren et al. (2009) — see References below

### Step 8: Subsample Ratings
- Randomly sampled 2,000 users and kept all their ratings (~610K ratings, down from 17.2M)
- **Justification:** The full dataset is slow to iterate on and exceeds GitHub's file size limit. Subsampling is standard practice for academic RS work — the MovieLens benchmarks (100K, 1M, 25M) are all subsampled from larger datasets. Random user sampling preserves the natural distribution of rating behaviour.
- **Reference:** Harper & Konstan (2015) — see References below

### Step 9: Save Processed Data
- Saved four clean CSV files to `data/processed/`

## Mood-to-Genre Mapping

The TMDB dataset has no explicit mood field. We define a rule-based mapping from user-selected moods to movie genres, grounded in **Mood Management Theory** (Zillmann, 1988).

### Mapping

| Mood | Genres | Rationale | Reference |
|---|---|---|---|
| Happy | Comedy, Animation, Family, Music | Happy viewers seek light content that maintains positive state | Zillmann (1988); Knobloch-Westerwick (2007) |
| Sad | Drama, Romance, Comedy | Sad viewers seek catharsis (drama) or mood repair (comedy) | Zillmann (2000); Koopman (2015) |
| Stressed | Comedy, Animation, Family, Documentary | Stressed viewers need relaxation and escapism | Winoto & Tang (2010); Qiao (2021) |
| Excited | Action, Adventure, Thriller, Science Fiction | Excited viewers seek high-arousal content matching their energy | Greenwood (2010) |
| Romantic | Romance, Drama, Comedy | Romantic mood calls for love stories and emotional narratives | Winoto & Tang (2010) |
| Bored | Adventure, Action, Science Fiction, Mystery, Horror | Bored viewers need stimulating, unpredictable content | Zillmann (1988); Knobloch-Westerwick (2007) |

### Design Decisions

1. **Six moods** — selected for practical coverage and user intuitiveness
2. **Multiple genres per mood** — ensures sufficient movie coverage
3. **Overlapping genres** — e.g., Comedy appears in Happy, Sad, and Stressed (serves different mood-regulation functions)
4. **Mood-repair as primary strategy** — negative moods map to positive-arousal genres, consistent with MMT
5. **Mood-congruent options included** — Sad includes Drama for viewers seeking catharsis (Koopman, 2015)

### Validation

The mapping was validated against the dataset to ensure each mood has sufficient movies (see `03_mood_genre_mapping.ipynb`).

## Prototype (Streamlit App)

The prototype is a Streamlit web application (`app.py`) that turns the three
implemented algorithms into a working mood-based movie recommender.

### Run Locally

```bash
pip install -r requirements.txt
streamlit run app.py
```

The app loads the processed data from `data/processed/` and the precomputed
models from `models/` (committed to this repository), so it starts in seconds
without retraining. If `models/` is ever deleted, rebuild it first:

```bash
pip install -r requirements-dev.txt   # scikit-learn + matplotlib, offline scripts only
python scripts/prepare_models.py      # rebuild models/
python scripts/run_evaluation.py      # regenerate output/ charts + metrics (optional)
```

### What It Does

```text
Select User  →  Select Mood  →  Recommend  →  Top-N ranked movies
```

1. **Movie Recommendations** — pick one of the three pre-tested demo users,
   see the user's already-rated movies in the
   collapsible "Already watched" panel, pick one of six moods, choose Top-N
   (5/10/15/20) and an algorithm (Collaborative / Content-Based / Hybrid,
   default Hybrid), then press **Recommend Movies**. Each result card shows
   the rank, title, genres, predicted rating and a short explanation.
2. **Algorithm Comparison** — the same user and mood run through all three
   algorithms side by side.
3. **Evaluation Results** — the offline metrics and charts from
   `scripts/run_evaluation.py` (RMSE/MAE table, error distribution, alpha
   tuning, Precision@K / Recall@K / F1@K, mood coverage).

### Design Rules Implemented

- **Mood filtering first** — candidates = mood-matching movies − movies the
  user already rated; only then are the algorithms applied (plan flow:
  Mood → Genre Filter → Algorithm → Rank → Top-N).
- **Cold-start fallback** — users with fewer than 20 ratings get mood-matched
  movies ranked by a Bayesian-weighted popularity score instead of an error.
- **Candidate starvation** — if the mood filter leaves fewer usable movies
  than requested, the remaining slots are filled from the popularity ranking.
- **Button-triggered computation** — recommendations are calculated only when
  the button is pressed, never on every widget change.
- **Precomputed everything** — TF-IDF, item-item and user-user similarity
  matrices are built once offline; the app never retrains at request time.
